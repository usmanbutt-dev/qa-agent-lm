# v0.1 Browser Layer Verification

## Scope

Version 0.1 proves the deterministic browser layer before any language model is connected. The implementation includes versioned tool contracts, a restricted Playwright session, bounded element observations, reference-based interactions, redacted diagnostic evidence, terminal outcomes, and a local demo application.

## Reproduce

Install the environment and browser:

```powershell
uv sync --locked --dev
uv run playwright install chromium
```

Run all quality gates:

```powershell
uv run ruff format --check .
uv run ruff check .
uv run mypy
uv run pytest
```

Run the demo application separately:

```powershell
uv run python demo/app.py
```

Open `http://127.0.0.1:8000`. The page exposes a successful check, an intentional HTTP 500 failure, and a sensitive action that requires human approval.

## Verified workflows

- Success: navigate, inspect, enter an environment, click the passing action, capture a screenshot, and finish with `pass`.
- Failure: run the intentional failure, collect console and HTTP evidence, capture a screenshot, and finish with `fail`.
- Human handoff: detect the destructive shared-data action and terminate with a `sensitive_action` help request.
- Timeout: exhaust the wall-clock budget and verify deterministic browser cleanup.

Generated screenshots and metadata are written under the configured artifact directory and ignored by Git.

## Remaining limitations

- No language model, planning loop, dataset, or fine-tuned adapter is connected yet.
- Element naming uses a bounded pragmatic accessibility approximation, not a complete browser accessibility tree.
- Screenshot masking covers DOM text, form values, and attributes; it cannot redact pixels drawn by canvas, video, or cross-origin embedded content.
- The artifact store is local filesystem storage and assumes one configured directory per concurrent session.
- The demo application is intentionally narrow and is not a production web service.
